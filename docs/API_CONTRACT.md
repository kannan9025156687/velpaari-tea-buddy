# API Contract — Velpaari Tea Buddy

This document is the agreement between three pieces of code that will be built at different times and must not need to see each other's source to agree:

1. **`shared/services/storage.js`** and its adapters (built in Phase 2–8, mock-backed)
2. **`shared/services/adapters/appsScriptAdapter.js`** (built in Phase 8, wired in Phase 10)
3. **`backend/Code.gs`** and its `*Service.gs` files (built in Phase 9)

Every field name, action name, and response shape below is final. If Phase 9 needs to deviate, this document is updated first, and any frontend code built against the old contract is revisited.

---

## 1. The `storage.js` interface (what business logic actually calls)

Regardless of which adapter is active, every call site in `customer/` and `admin/` uses this exact shape:

```js
await storage.create(collection, data)          → { success, data, error }
await storage.read(collection, id)               → { success, data, error }
await storage.update(collection, id, patch)       → { success, data, error }
await storage.query(collection, filters, options)  → { success, data: [...], error }
await storage.remove(collection, id)                → { success, error }
```

- `collection` — a string constant from `config/constants.js` (currently only `'orders'` is used; the shape supports future collections without a contract change).
- Every response, from every adapter, follows the same envelope:

```js
// success
{ success: true, data: <result>, error: null }

// failure
{ success: false, data: null, error: { code: "STRING_CODE", message: "human-readable" } }
```

No call site ever needs to know which adapter answered it — this envelope is identical whether the answer came from `localStorage`, Apps Script, or (eventually) Firebase.

### Standard error codes

| Code | Meaning |
|---|---|
| `NOT_FOUND` | `read`/`update`/`remove` referenced an ID that doesn't exist |
| `VALIDATION_ERROR` | Payload failed validation (client-side or server-side) |
| `NETWORK_ERROR` | `appsScriptAdapter` request failed or timed out |
| `STORAGE_UNAVAILABLE` | `localStorage` blocked/full, or adapter otherwise can't operate |
| `UNKNOWN_ERROR` | Anything uncategorized — should be rare and logged |

## 2. `orders` collection — data shape

This is the object every adapter stores and returns for the `'orders'` collection. It is also, not coincidentally, close to the eventual Google Sheets row shape (see `SHEET_SCHEMA.md`).

```js
{
  orderId: "TB-20260725-0001",        // generated server-side once Phase 9 is live;
                                        // generated by shared/utils/idGenerator.js in mock phases
  customer: "Kannan",
  phone: "9025156687",                 // optional
  items: [
    { id: "tea", name: "Tea Parcel", qty: 2, price: 79 },
    { id: "biscuit", name: "Biscuit", qty: 1, price: 10 }
  ],
  total: 168,                          // MUST be server-recomputed once backend is live — see §5
  location: {
    lat: "11.016800",                  // string, fixed 6 decimals — or null if manual
    lng: "76.955800",
    mapsUrl: "https://www.google.com/maps?q=11.016800,76.955800"
  },
  // — OR, if GPS was denied —
  location: { manual: "12, Race Course Road, Coimbatore" },

  status: "NEW",                       // one of ORDER_STATUS in config/constants.js
  estimatedMinutes: { min: 10, max: 15 },
  device: "Linux armv8l",
  browser: "Mozilla/5.0 ...",
  createdAt: "2026-07-25T09:41:00.000Z"  // ISO string
}
```

`storage.create('orders', payload)` is called **without** `orderId`, `status`, or `createdAt` — the adapter fills those in (mock adapter using `idGenerator.js`; Apps Script adapter receiving them back from the server, which is authoritative).

## 3. Query filters used against the `orders` collection

`storage.query('orders', filters, options)` — filters supported by every adapter identically:

```js
{ status: "NEW" }                                  // exact match
{ dateFrom: "2026-07-25", dateTo: "2026-07-25" }     // inclusive date range, by createdAt
{ search: "kannan" }                                  // matches customer name or orderId, case-insensitive
```

`options`:
```js
{ sort: "createdAt_desc" | "createdAt_asc", limit: 50 }
```

## 4. Backend actions (what `appsScriptAdapter.js` sends, what `Code.gs` must implement)

The Apps Script Web App is deployed **`Anyone`** access, so all requests use **`GET`** with query parameters, or **`POST` with a `text/plain` body** (never `application/json`) — this avoids a CORS preflight `OPTIONS` request, which Apps Script Web Apps cannot answer.

Base URL placeholder: `{APPS_SCRIPT_URL}` — the deployed Web App `/exec` URL, stored in `config/appConfig.js` once Phase 9 is complete.

Every request includes an `action` parameter. Every response is JSON matching the envelope in §1.

| `action` | Method | Params | Maps to `storage.js` call |
|---|---|---|---|
| `createOrder` | POST (text/plain, JSON-encoded body) | order payload (§2, minus server-filled fields) | `storage.create('orders', payload)` |
| `getOrder` | GET | `?orderId=TB-...` | `storage.read('orders', orderId)` |
| `getOrders` | GET | `?status=&dateFrom=&dateTo=&search=&sort=&limit=` | `storage.query('orders', filters, options)` |
| `updateOrderStatus` | POST (text/plain) | `{ orderId, status }` | `storage.update('orders', orderId, { status })` |
| `getTodayStats` | GET | — | (admin-only, not part of the 5 core CRUD ops — see §4a) |
| `getWeeklyStats` | GET | — | same |
| `getMonthlyStats` | GET | — | same |

### 4a. Stats actions (admin dashboard cards)

These don't map to generic CRUD, so `dashboardStats.js` calls them directly through a small `statsService` on top of `apiClient` — not through `storage.js`'s five generic methods. Response shape:

```js
// getTodayStats response .data
{
  ordersCount: 14,
  revenue: 1846,
  pending: 3,       // NEW + PREPARING
  completed: 11
}
```

`getWeeklyStats` / `getMonthlyStats` return the same shape, aggregated over the wider window, plus:
```js
{ ...above, topItems: [ { id: "tea", name: "Tea Parcel", qty: 42 }, ... ] }
```

### 4b. Example request/response — `createOrder`

**Request** (POST, `Content-Type: text/plain`, body is a JSON string):
```json
{
  "action": "createOrder",
  "payload": {
    "customer": "Kannan",
    "items": [{ "id": "tea", "name": "Tea Parcel", "qty": 2, "price": 79 }],
    "location": { "manual": "12, Race Course Road, Coimbatore" },
    "device": "Linux armv8l",
    "browser": "Mozilla/5.0 ..."
  }
}
```

**Response:**
```json
{
  "success": true,
  "data": {
    "orderId": "TB-20260725-0001",
    "customer": "Kannan",
    "items": [{ "id": "tea", "name": "Tea Parcel", "qty": 2, "price": 79 }],
    "total": 158,

    "status": "NEW",

  },

}
```

## 5. Server-side validation contract (`Validation.gs`, Phase 9)

The backend never trusts these client-supplied fields at face value:

- **`total`** — always recomputed server-side from `items[].qty × Config.gs`'s authoritative price for `items[].id`. A mismatched client-supplied total is silently discarded, not trusted.
- **`items[].id`** — must exist in the server-side menu list; unknown IDs reject the whole request with `VALIDATION_ERROR`.
- **`items[].qty`** — integer, `1 ≤ qty ≤ 20` (configurable), else `VALIDATION_ERROR`.
- **`customer`** — string, trimmed, `1–60` characters.
- **`location.manual`** — string, trimmed, capped at 200 characters, and never written to a Sheet cell starting with `=`, `+`, `-`, or `@` (formula-injection guard — such a value is prefixed with a `'` before writing).
- **`status`** (on `updateOrderStatus`) — must be one of the `ORDER_STATUS` enum values in `Config.gs`; anything else is rejected.

Any validation failure returns the standard error envelope with `code: "VALIDATION_ERROR"` and a `message` describing the first failing field — never a partial write.

## 6. Timeouts & retries (`apiClient.js` contract)

- Default timeout: **8000ms** per request (configurable via `config/appConfig.js`).
- On `NETWORK_ERROR` or timeout, `apiClient.js` retries **once** automatically before surfacing the error to the caller.
- Callers (`orderService.js`, `orderAdminService.js`) treat a final failure the same way regardless of cause — show a toast (`shared/components/toast.js`) and, for order confirmation specifically, offer a "Try Again" action rather than losing the customer's cart.

---

## 7. What does *not* change between mock and real backend

Everything in §1–3 is identical whether `STORAGE_MODE` is `'localStorage'` or `'appsScript'`. Only §4–6 (the Apps Script–specific wire format) exists solely inside `appsScriptAdapter.js` and `backend/`. No page, component, or `*Service.js` file outside of `shared/services/` should ever reference an `action` name, a query-string, or a `text/plain` body directly.
